# 文档同步清单（改完必须同步手册）

> 义务本身是硬规则：**每次修改完成后，必须在同一批改动里完成受影响手册的修改**（与代码一起提交）。
> 手册滞后就是上次全面审计发现 16 类过时断言的根因。本页是**怎么做**。

## 谁做、什么时候

- **worker 不改文档**：完成代码后列出「受影响文档 + 需同步要点」，由 **main** 代改并随代码一起提交
  （同一分支；可追加提交，或验收前修入原提交）。
- 文档与代码**同批**：不要留「以后再补」；跨批次再补就要重新对账。

## 改什么，就同步哪本

| 改动 | 同步到 |
|------|--------|
| `src/core/klippy/` 的行为、结构、模块增删 | [开发手册](../../../docs/klippy/developer-manual/README.md)对应页（**模块表 + 专题页都要改**） |
| G-Code 命令增删改、配置节/选项增删改 | [G-Code 命令参考](../../../docs/klippy/user-manual/gcode-commands.md) / [配置文件参考](../../../docs/klippy/user-manual/config.md) |
| 客户端交互、日志行为 | [客户端使用](../../../docs/klippy/user-manual/client.md) / [日志与调试](../../../docs/klippy/user-manual/logging.md) |
| `klippy-api` / `klippy-client`、线上形状、端点 | [第三方开发手册](../../../docs/klippy/third-party-dev/README.md)（`api-reference.md` 与端点状态表一起改） |
| 新增模块或测试、覆盖变化 | [测试](../../../docs/klippy/developer-manual/testing.md) 的覆盖清单（**测试计数要重数**） |
| 回归数字、忽略列表、转绿状态 | [回归测试](../../../docs/klippy/developer-manual/regression-tests.md) |
| 与上游行为/形状不同 | [上游偏移表](../../../docs/klippy/developer-manual/upstream-deviations.md) |
| 端口/协议/线上字节 | `serial-mux-protocol.md`（协议页）+ 用户手册的连接/配置页 |
| 真机项、硬件受限项 | [`TESTING.md`](../../../TESTING.md)（判定要可执行） |
| 未完成待办、留档缺陷 | [`TODO.md`](../../../TODO.md) |

## 三条硬要求

1. **写死的数字与名字必须重核**：测试名、端点条数、计数、二进制大小、工单号——提交前逐个对回**源码/实测**
   （`grep` 源文件数一遍；`cargo test -- --list | grep -c` 数一遍）。
2. **旧断言随实现一起改**：功能落地、工单完成、行为变更时，把手册与**源码注释**里对应的
   「尚未实现 / 待办 / 属某工单」一并改成现状，**不要留新旧两种说法**。
3. **已完成的任务标号不得再被引用**：`TODO.md` 与 `docs/work-log/` 里的任务/问答标号（`D3`/`F8b`/`T3`/`Q2`/`H1-3`…）
   一旦完成，就不得再出现在**其他文档与源码注释**里——改为陈述现状或注明「已归档」，连带的「见 TODO X」
   「属 X」「X 待办」一并清理。**豁免**：`TODO.md` 与 `docs/work-log/` 自身是台账/档案，历史标号照留。

## 提交前自查

- 手册里关于**被改对象**的每句话，现在还能对着源码成立吗？（逐句过一遍，别只看新增段）
- 新增内容里的**常量/命令字节/函数名/文件路径**是否都对着源码核过？没核的标「未核实」。
- 交叉引用是否仍然有效（相对路径、锚点）；删了东西以后有没有死链。
- 细则见 [测试 → 文档同步](../../../docs/klippy/developer-manual/testing.md#文档同步)。

## 删档案前先分流

要删工作记录/调研笔记一类过程档案时，先把「唯它才有的规范信息」**分类搬进规范文档**：

| 内容 | 去处 |
|---|---|
| 运行机制/设计规则 | 协议页或开发手册专题页 |
| 与上游差异 | `upstream-deviations.md` |
| 硬件受限项/真机项 | `TESTING.md` |
| 未完成待办、留档缺陷 | `TODO.md` |
| 操作手法（工具/设备/流程） | 对应 skill（如 [`flash-firmware`](../flash-firmware/SKILL.md)） |

然后**清掉所有指向它的引用**，只留一句**非链接**的溯源说明（写清「原件已删、用
`git log --diff-filter=D -- docs/work-log/` 回溯」），并确认删除后没有死链。
