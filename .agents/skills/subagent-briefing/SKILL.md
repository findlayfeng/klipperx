# 子代理任务书（怎么给活）

> 事故驱动：有一个单元前三次尝试各 30 分钟**零产出**（侦察挤爆预算），任务书里写上「立即落笔 /
> 10 分钟内首个提交 / 增量提交」后，第四次 30 分钟内 2 个提交完成。**任务书写法与产出强相关。**

## 一个 worker 只给一个最小单元

- 判据：**失败了能单独重试、不必了解别的单元细节、产出能单独验收**。不满足就继续拆。
- 一个 task 只写一个目标、一份验收、一个预期输出；要列多处不相干改动 ⇒ 拆分不够，回去再拆。
- 无依赖的单元一律并行（各自 worktree）；有**知识依赖**的（下一个单元要先知道上一个的布线/坑）按依赖排队。
- **任务书自带规格**：写手要读的同一份文件不要再派 scout；规格已知就直接写进任务书（带 `file:line`）。

## 六要素模板（缺一项都算任务书不合格）

```
【<单元名>：<一句话目标>】

目标（最小单元，只此一个）：…

目录/边界：
- 工作区：<绝对路径>（分支 <agents/…>，基 <commit>；本 worktree 只有你一个写者）
- 可改：<文件清单>；禁止改：<文档/third_party/…>
- 构建验证只写自己的临时目录（KCONFIG_CONFIG/OUT 外移）；worktree 里 cargo 要内联
  KLIPPERX_KLIPPER_DIR=<主检出>/third_party/klipper

已核实的现状与规格（直接用，禁再侦察）：<file:line 级的事实、公式、字节、文案>

实现要点：<列 3–6 条，含必须满足的约束>

约束（Worker 纪律，必须遵守）：
- <纪律块，见下>

验收标准（逐条给证据）：
1. <可复现的判定：测试名 + 两次运行数字/耗时，或构建配置 + 告警数>
2. fmt / build / 全量闸门数字
3. 提交到本分支（<提交信息风格>）

预期输出（直接回传，不落文件）：<改动清单、新增 API、测试名与数字、坑、文档清单+同步要点、
不确定点、停止条件声明>
```

## 纪律块（原样抄进「约束」节）

- 禁止上下文压缩/摘要工具；上下文吃紧就停下报告（由 main 裁棒换棒续做）。
- **防超时三板斧**：立即落笔（读完模板就写第一版）／**10 分钟内必须有首个提交**（WIP 也算）／
  每步增量提交；只读编译/测试错误点名的文件，禁探索式 `grep`。
- 命令形式：bash **单条命令**，禁 `2>&1`/`|`/`>`/`;`；改文件用 `edit`/`write`（禁 heredoc、`sed -i`）；
  测试窄过滤 + `timeout`；普通测试禁 `KLIPPERX_TRACE=1`。
- 测试必须整体有界（加 `tokio::time::timeout` 之类兜底），禁止写出能挂住 CI 的用例。
- 禁止 `git checkout --`/`restore`/`stash`/`clean`；看到不属于自己的改动**只报告不清理**；
  不 `push`/`fetch`/`merge`/`rebase`，只在本分支提交。
- 改 `third_party/`（上游子模组）或固件前**先停下报告**，由 main 裁决。
- 遇超时按**三件套**报：① 进度（已提交/未提交、已证事实）② 卡点证据（卡在哪步 + 日志尾部）
  ③ 建议下一步；先自行有界复核 ≤15 分钟。
- 不得再向下委派子代理。

## 派什么角色

| 任务 | 角色 | 要点 |
|---|---|---|
| 规格未知（上游语义/本仓落点/依赖链） | `scout`（只读） | 产出「可直接抄进任务书的规格」：带 `file:line`、公式/文案、落点与缺口；**可与写手并行**；产出直接回传 |
| 写代码/文档/测试 | `worker` | 见上；一个最小单元 |
| 评审已完成的改动 | `reviewer`（只读） | 给**逐条核对清单 + 证据要求 + 分级裁定**（P0/P1 阻塞 / P2 建议 / 报告） |
| 需要独立证据核查 | `evidence-auditor` | 与主线并行 |

- 评审/侦察子代理**没有 shell**：它的逐文件结论要 main 补 `git show --stat <commit>` / `git show <commit> -- <file>`
  贴回去（见 [`AGENTS.md`](../../../AGENTS.md) 规则 9）。
- 子代理出事的救援流程（挂死/超时/`content_filter`）见 [`subagent-rescue`](../subagent-rescue/SKILL.md)。

## 派出之后

- 默认**异步**派发并让出控制权（完成会唤醒）；只有本轮必须拿到结果才阻塞等待。
- 看到「长时间无活动」先**看进程状态**再决定 steer/resume（全线程 `futex_wait` + CPU≈0 = 在等），
  别急着重跑。
- 收口时由 main 做：集成、冲突消解、全量闸门、手册同步、合并（ff / `--no-ff` 判定见
  [`task-branch-flow`](../task-branch-flow/SKILL.md)）。
