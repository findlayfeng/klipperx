# FW5e-2 动工记录：`[stepper_*]`/`[printer]` 装载、`G1` 与连接期读回（2026-09-21）

本文记录 FW5e 第二半（`[stepper_*]`/`[printer]` section 注册、`G1`/`G4`、真板读回）实际
落成什么样、哪些按用户决定后置。规范以代码与 `TODO.md` 为准；这是**一次性**记录。

## 0. 结论

| 项 | 结果 |
|---|---|
| `[stepper_x/y/z]` section | ✅ 新 `extras/stepper.rs`；按 `section!` 注册在 generic 阶段；对象**不可查询**（对齐上游「stepper 不是 printer object」） |
| `[printer]` → `toolhead` | ✅ `extras/toolhead.rs`；`phase = late, object = "toolhead"`，FW1 的住户机制如期用上 |
| G-Code | ✅ `G0`/`G1`（绝对坐标 + `F` mm/min）、`G4`（`P` ms / `S` s）、`M400`、`SET_KINEMATIC_POSITION` |
| 连接期读回 | ✅ 每个 stepper 在 connect 发 `stepper_get_position`，把固件步数换算成求解器位置，并把压缩器锚在当时的时钟 |
| step 下发 | ✅ connect 起后台任务每 10 ms 生成并 `await` 下发（`queue_step`），restart 时随对象停止 |

## 1. 两个 section 的形状

### `[stepper_*]`（`extras/stepper.rs`）

- 工厂 `load_config` 三个 `section!` 共用；段名 `stepper_x` → `Axis::X`（`axis_from_name`）。
- 选项：`step_pin`/`dir_pin`、`rotation_distance`、`microsteps`、`full_steps_per_rotation`
  （默认 200、须为 4 的倍数）、`gear_ratio`（`g1:g2` 连乘）、`step_pulse_duration`
  （默认 2 µs）、`position_min`/`position_max`/`position_endstop`。
- `step_dist = rotation_distance / (full_steps * microsteps * gear_ratio)`
  （上游 `parse_step_distance`）。
- 引脚经 `PrinterPins::setup_stepper`：`lookup_pin` 两次（步进/方向），校验同一 MCU，
  步进脚 `!` → `invert_step=1`，方向脚 `!` → 线上方向翻转。
- 对象注册名是段名（`stepper_x`），`is_queryable()=false`：上游该节不产生 printer object，
  所以 `objects/list` 看不到它，但装载器认它、`[printer]` 能 `lookup_object_as`。

### `[printer]`（`extras/toolhead.rs`）

- `kinematics` 只认 `cartesian`（其余报上游式 `Error loading kinematics '<x>'`，
  完整错误链是 `[printer]: …`）。
- 读 `max_velocity`/`max_accel`（必填）、`minimum_cruise_ratio`、`square_corner_velocity`、
  `max_z_velocity`/`max_z_accel`，按上游公式算 `junction_deviation` 与 `mcr_pseudo_accel`。
- `new()` 里 `lookup_object_as::<PrinterStepper>("stepper_x/y/z")`，缺一即配置错。
- `connect()`：取三个 `motion::Stepper`（`PrinterStepper::take_stepper`，此时带 oid 与
  `mcu_freq`）→ 组 `ToolHead` + `CartesianKinematics`（range 来自各 `[stepper_*]` 的
  `position_min/max`）→ 建 `McuClock`、`get_uptime` seed → `set_estimated_print_time` →
  `warn_and_wait` → 存状态、`tokio::spawn` 下发任务。

## 2. 连接期读回（`stepper_get_position`）

对齐上游 `MCU_stepper._query_mcu_position`（`klippy/stepper.py:212`）：

1. `McuStepper::query_position` 发 `stepper_get_position oid=%c`，收 `stepper_position oid=%c pos=%i`；
   方向脚 `!` 时取负。
2. 步数 → 毫米：`pos * step_dist`，写进 `StepKinematics::commanded_pos`。
3. 压缩器锚点：`set_time(clock/mcu_freq, mcu_freq)` + `set_last_position(clock)`，
   `clock` 取 `Mcu::estimated_clock()`（`McuObject::connect` 已 seed）。

这样第一次 `queue_step` 的 `interval` 是相对固件的「现在」而不是 print time 0，避免把首步
排到过去（固件会立刻执行，但绝对时基会错位）。

## 3. 与 FW5 动工前调查原建议的偏差（记录，避免下次困惑）

| 原建议 | 实际 | 原因 |
|---|---|---|
| `warn_and_wait` 在**第一次真正要 `queue_step`** 时调 | 放在 `[printer]::connect`（async） | 第一次 flush 在同步回调里，无法 `await`；放 connect 仍在任何运动之前，且是最近的可等待点 |
| flush 用 `Reactor::register_timer` 定时回调 | connect 后 `tokio::spawn` 一个 10 ms 循环 | 下发要 `await` 传输背压（`Mcu::send_payload`）；回调是同步的。任务在对象 `Drop` 时经 `shutdown` 标志退出 |
| 首步 buffering | 生成全部已规划步（`step_gen_time = print_time`） | 简化压缩器无所谓窗口；完整压缩（FW5f）再按上游 `BGFLUSH_*` 对齐 |

`G1` 无 `gcode_move` 层（H3）：坐标就是 toolhead 坐标，没有偏移、相对模式、挤出因子；
纯 E 移动会记录位置但不产生步（没有 `[extruder]`）。

## 4. 留给后续

- **真板验收**（用户决定）：`stepper_get_position`、单轴/三轴 `G1`、`G28`（F8）——等 FW5f
  的完整压缩把 `queue_step` 数量压下来之后再上真机，避免「Move queue overflow」。
- **FW5f**：`(interval, count, add)` + `max_error` 的完整 `stepcompress`，与上游对拍。
- **FW6/F8**：`HomingState`、`endstop_pin`、`homing_speed` 等；`[stepper_*]` 现在已把
  `position_endstop` 读进来存着，`G28` 接上时直接用。
- **stepper_enable**（H?）：`enable_pin`、`M18/M84`；`step_pulse_duration` 已支持。
- `gcode_move`（H3）：偏移、相对坐标、`M114`、挤出因子。

## 5. 测试

- `extras/stepper.rs`：8 个（轴名映射、step_dist、gear_ratio、缺选项、跨 MCU、endstop 范围、装载）。

  `G4`、`SET_KINEMATIC_POSITION`）。

- `mcu/resource/stepper.rs`：新增方向脚翻转的 1 个。

真板读回与下发路径按用户决定不在本轮验证。
