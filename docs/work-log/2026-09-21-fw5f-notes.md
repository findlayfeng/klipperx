# FW5f 动工记录：`stepcompress` 完整压缩（2026-09-21）

本文记录 FW5f（把 FW5c 的“每步一条 `queue_step`”简化实现换成上游完整压缩）实际怎么
做的、怎么和上游对拍、还剩什么。规范以代码与 `TODO.md` 为准；这是**一次性**记录。

## 0. 结论

| 项 | 结果 |
|---|---|
| 算法 | ✅ 直译 `chelper/stepcompress.c`：`minmax_point` / `compress_bisect_add` / `check_line` / `add_move` / `queue_flush` / `queue_append`（含 far 与 64K 扩展）/ `set_next_step_dir` / `append` / `commit` / `flush` / `set_last_position` |
| 时钟模型 | ✅ 与上游一致：内部队列存低 32 位时钟，`last_step_clock` 64 位；`set_time` 按 `last_step_clock` 重算 `last_step_print_time`，于是 `step_clock = floor((print_time + step_time - mcu_time_offset) * mcu_freq + .5)`，与 `last_step_clock` 无关 |
| 误差 | ✅ `max_error = 25 µs * mcu_freq`（`MAX_STEPCOMPRESS_ERROR`，`stepper.py:19`）；`QUADRATIC_DEV=11` |
| 校验 | ✅ `check_line` 常开（`CHECK_LINES=1`）；失败沿 `itersolve` → `MotionQueuing` → flush 任务上报 `Internal error in stepcompress` 并 `invoke_shutdown` |
| 对拍 | ✅ 自建上游 C harness（stub `message_alloc_and_encode`/`errorf`）生成 8 组向量，逐条写进 `motion/stepcompress.rs` 单测 |
| 简化版告警 | ✅ 删除生产调用；`GracePolicy`/`warn_and_wait` 保留（测试与未来 fallback） |
| 真板验收 | ✅ 新 `klipperx stress --task motion`：真板 500 步 → 3 条命令，`stepper_get_position` 读回 500 |

## 1. 与上游的逐式对应

- `minmax_point`：`point = clock32 - (u32)last_step_clock`，`prevpoint` 同法；
  `max_error = min((point-prevpoint)/2, sc.max_error)`；返回 `(point-max_error, point)`。
- `compress_bisect_add`：外层按 `add` 二分（`add = maxadd - (maxadd-minadd)/4`），内层取
  最长可行区间；`count>0x200` 后停止；`zerocount + zerocount/16 >= bestcount` 时优先
  `add=0`。**为防溢出，中间量用 `i64`**（C 用 `int32_t`；向量对拍证明在本项目输入范围内
  结果一致）。
- `idiv_up` / `idiv_down`：保留上游对负数的取整方向。
- `add_move`：`ticks = add*count*(count-1)/2 + interval*(count-1)`（低 32 位），
  `last_step_clock = first_clock + ticks`。
- `queue_append_far`：pending 步离 `last_step_clock` 超过 `CLOCK_DIFF_MAX (3<<28)` 时，先
  `queue_flush(step_clock-CLOCK_DIFF_MAX+1)`，再要么 `flush_far` 发一条大 `interval` 的单步
  （连接后第一次下发的“重锚”），要么入队。
- `append` 的 step+dir+step 过滤：`diff < SDS_FILTER_TIME * mcu_freq` 时回滚**待发步**并
  丢弃当前步，方向记为当前方向（与上游一致；见 `CASE sds_filter_mhz`）。

## 2. 与上游向量对拍

`/tmp` 下的一次性 harness（`#include "stepcompress.c"` + stub）用 `max_error=40`、
`mcu_freq=1`（`set_time(.5, 1)`，使 `step_clock` 恰为整数），覆盖：

| 向量 | 结果 |
|---|---|
| `constant_positive` | `(1000,10,0)` |
| `accelerate` | `(2989,12,-198)` |
| `decelerate` | `(989,12,252)` |
| `quadratic` | `(2000,20,50)` |
| `jitter`（40 步伪随机间隔） | 12 条 move，逐条形同 |
| `far_gap` | `(900000000,1,0)` + `(1000,2,0)` |
| `single` | `(1234,1,0)` |
| `direction_change` | dir 1 → `(1000,8,0)` → dir 0 → `(1000,8,0)` |
| `sds_filter_mhz`（1 MHz） | dir 1 → `(1000,1,0)`（0.002/0.00205 两步都被回滚丢弃） |

这些期望值直接写在 `motion/stepcompress.rs` 的 `test_*_matches_upstream` 里。另有
`test_a_compressed_run_reconstructs_every_requested_step`：把压缩结果反向展开，要求每个原始
步时刻都落在 `max_error` 窗口内，且 200 步压到 ≤8 条命令。

## 3. 连带改动

- `motion/stepcompress.rs`：`StepCompressError`；`StepCompressor` 重写；`StepMove`/`Points`。
- `motion/itersolve.rs`：`generate_steps` / `gen_steps_range` 返回 `Result`，`commit`/`append`
  的 `?` 上抛。
- `motion/stepper.rs` / `queuing.rs` / `toolhead.rs`：`generate` / `flush_step_generation`
  返回 `Result`，`move_clock` 改 `u64`。
- `extras/toolhead.rs`：flush 任务收到 `StepCompressError` 时 `invoke_shutdown`；去掉
  `warn_and_wait` 的生产调用；`Connected::generate` 先 `wait_moves()` 再取生成时间。
- `extras/stepper.rs`：连接时按“print_time 0 = clock 0”设 `set_time(0.0, freq)`，再
  `set_last_position(clock, steps)`。
- 计数类单测从“数命令条数”改为“数 `count` 之和”（压缩后条数不再等于步数）。

## 4. 真板验收（2026-09-21）

板子：STM32F103xe，72 MHz，`/dev/serial/by-id/usb-Klipper_stm32f103xe_39FFD7054D47323924610951-if00`。

现有 `stress` 只压手写 `queue_step`，没有走压缩器；而完整 `G1` 需要 `[printer]` 的三轴，
本项目 `config.cfg` 只（注释）给了 X 的 `PB0/PB1`，Y/Z 未知，不能安全地拿未知引脚充当轨道。
因此给 `stress` 加了 `--task motion`：用 X 的 step/dir 引脚单独配置一个 stepper，走真的主机链路
（`Trapq` → `itersolve` → 完整 `stepcompress` → 分批下发），再用 `stepper_get_position` 读回。

```
using [stepper_x] -> step_pin=16 dir_pin=17
configured stepper oid 0 (firmware move queue: 1024 slots)
generated 3 command(s) for 500 step(s): 500 step(s), 1 dir command(s)
firmware position: 500 step(s), expected 500
motion smoke OK
```

即：5 mm / 10 mm/s（`step_dist=0.01`，500 步）被压成 1 条 `set_next_step_dir` +
2 条 `queue_step`；固件自己数出的步进数正好 500。中途踩过一次坑：print_time 写死 1.0 s
时，第一段排到板子当前时钟之前～秒级，第二段触发 `Stepper too far in past`；改成先用
`get_uptime` seed `estimated_clock`、再从「板子现在 + 100 ms」起算就好了（与生产路径一致）。

仍然没做的：完整 `[printer]`/`G1`/`G28` 真板验收，需要知道三轴接线（或后续 FW6/F8）。

## 5. 留给后续

- **真板验收**（下一步）：单轴/三轴 `G1`、`stepper_get_position` 读回、`M400`/停止、
  `G28`（FW6/F8）。届时可再核 `queue_step` 条数与固件 move queue 余量。
- **history/`find_past_position`/`extract_old`**：本阶段只做压缩；这两支是
  `motion_report`（`dump_trapq`/`dump_stepper`）的消费者，随它落地。
- **`mcu_time_offset` 校准**：目前 `set_time(0.0)`，即假设 host 的 `estimated_print_time`
  与固件时钟零漂移；上游每个 `stats` 周期用 `calibrate_clock` 重设 offset/freq。漂移补偿
  随后续 `stats` 消费者补。
