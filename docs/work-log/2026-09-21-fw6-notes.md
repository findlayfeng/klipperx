| 项 | 结论 |

| FW6 的验收（TODO） | 「一个 endstop + `query_endstops/status`」**不需要回零**：`MCU_endstop` + `query_endstops` 对象 + 一个端点即可 |

### 1.2 关键契约

**`MCU_trsync`（`mcu.py:155-339`）**：每个 MCU 一个，持 `config_trsync` oid 与自己的
命令队列；`add_stepper` 把该 MCU 上的 stepper 登记为触发信号。
- `start(print_time, report_offset, completion, expire_timeout)`：
  `clock = print_time_to_clock(print_time)`、`expire = clock + seconds_to_clock(timeout)`、
  `report_ticks = seconds_to_clock(timeout*.3)`、
  `report_clock = clock + report_ticks*offset`、`min_extend = report_ticks*.8`；
  然后 `trdispatch_mcu_setup` → `trsync_start`（`reqclock=clock`）→ 每 stepper
  `stepper_stop_on_trigger` → `trsync_set_timeout`。
- `_handle_trsync_state`：`can_trigger=0` 时完成 completion（reason≥COMMS_TIMEOUT 是失败）；
  `can_trigger=1` 时更新 `last_status_clock` 并（在多 MCU 取最慢者后）计算新的 `expire`，
  够 `min_extend_ticks` 就重发 `trsync_set_timeout`；`_home_end_clock` 到点则主动
  `trsync_trigger(REASON_PAST_END_TIME)`。
- `stop()`：`trsync_trigger(REASON_HOST_REQUEST)` 并读 `trsync_state`，对每个 stepper
  `note_homing_end()`，返回 `trigger_reason`。

**`TriggerDispatch`（`mcu.py:262-339`）**：每台 printer 一个；`add_stepper` 按 stepper 的
MCU 路由到对应 `MCU_trsync`，并检查「多 MCU 共享轴」不支持；`start` 建一个 completion、
把各 trsync 的 report_offset 错开、`trdispatch_start(REASON_HOST_REQUEST)`。

**`MCU_endstop`（`mcu.py:340-407`）**：`config_endstop` + `endstop_home`（`on_restart` 一条
全零的 reset）+ `endstop_query_state`。`home_start` 算 `clock`/`rest_ticks`、起 dispatch、
发 `endstop_home`（`pin_value = triggered ^ invert`）；`home_wait` 等 `wait_end`、关检查、
`stop()`，ENDSTOP_HIT 时读 `endstop_state.next_clock` 换算成触发 print time
（`next_clock - rest_ticks`）；`query_endstop(print_time)` 读 `pin_value ^ invert`。

**`cheper/trdispatch.c`**：多 MCU 的「取最慢 status、给各 MCU 延长 expire」都在 C 里，
通过 `serialqueue` 的 fastreader 直接读 `trsync_state` 原始字节。单 MCU 时
`min_tdm` 就是自己、`next_min_time=PR_NEVER→min_time`，逻辑退化成「把自己刚报告的
clock 当作已确认时间，再加 `expire_ticks` 重发超时」。

**`homing.py`**：`Homing` 是 toolhead 侧的回零状态（`set_axes`/`get_trigger_position`/
`set_stepper_adjustment`/`set_homed_position`/`home_rails`）；`HomingMove` 管一次回零移动
（`home_start` → `dwell(HOMING_START_DELAY)` → `toolhead.drip_move` → `home_wait` →
按 `StepperPosition.note_home_end` 记 halt/trig 位置 → `set_position(haltpos)`）。
`StepperPosition` 关键：`start_pos = stepper.get_mcu_position()`、
`halt_pos = get_mcu_position()`、`trig_pos = get_past_mcu_position(trigger_time)`。

**`GenericPrinterRail`/`LookupMultiRail`（`stepper.py:344-475`）**：`[stepper_x]` 的 rail：
`endstop_pin`（`lookup_endstop`，同 pin 复用 `endstop_map`）→ `MCU_endstop`；
`position_endstop`/`position_min`/`position_max`；`homing_speed`/`second_homing_speed`/
`homing_retract_speed`/`homing_retract_dist`/`homing_positive_dir`（可由 endstop 位置推断，
否则必须显式）；`add_stepper_from_config` 读 `step_pin`/`dir_pin`/`extra_steppers`；
`get_homing_info()` 给 `homing.py` 用；`query_endstops.register_endstop(mcu_endstop, name)`。

**`MCU_stepper` 的回零句柄（`stepper.py:164-228`）**：
- `get_mcu_position(cmd_pos=None)`：`round((cmd_pos + offset) / step_dist)`；
- `get_past_mcu_position(print_time)`：`stepcompress_find_past_position(clock)`；
- `note_homing_end()`：`stepcompress_reset(sc, 0)` + 发 `reset_step_clock oid clock=0` +
  `_query_mcu_position()`；`_query_mcu_position` 发 `stepper_get_position`，
  `stepcompress_set_last_position(clock, pos)`。
- `_set_mcu_position`/`_mcu_position_offset` 用于 probe 后的偏差校正。

**`query_endstops.py`**：一个对象收 `(mcu_endstop, name)` 列表，`get_status` 报
`{"last_query": {name: bool}}`；`query_endstops/status` webhook 返回
`{name: "open"|"TRIGGERED"}`；`QUERY_ENDSTOPS`/`M119` 打印一行。

## 4. 设计选项与建议

### (a) 命令队列与 `min_clock`/`req_clock`（**建议：单 MCU 用固件调度替代**）

上游 `serialqueue` 把消息按 `req_clock` 压住，到点才发。本仓库没有它，但：

- `trsync_start`/`trsync_set_timeout`/`endstop_home`/`queue_digital_out` 都携带**绝对时钟**，
  固件按该时钟调度，**发送时刻**不是关键（早发只会让它等）；
- 唯一需要「到点再发」语义的是 `MCU_bus_digital_out.update_digital_out(value, minclock,
  reqclock)`（`bus.py:361`），它用 `update_digital_out`（立即生效）+ serialqueue 定时。
  这里改成发 `queue_digital_out(reqclock, value)`——固件在 `reqclock` 才翻转，单 MCU 等价。

**决定**：不引入 host 侧 serialqueue；`Mcu` 仍是 FIFO 发送。`MCU_bus_digital_out` 用
`queue_digital_out`。多 MCU 时再评估（FW6e）。

### (b) `TriggerDispatch`/`MCU_trsync` 的移植（**建议：纯 Rust 单 MCU 状态机**）

上游是 C（`trdispatch.c`）+ `serialqueue` fastreader + 线程锁，为多 MCU 服务。单 MCU 时：

- `TriggerDispatch` 只有 1 个 `McuTrsync`；`start` 建 completion（我们的 `oneshot`/
  `Notify`），`stop`/`wait_end` 完成它；
- `McuTrsync` 用 `bind_event::<TrsyncState>` 收 `trsync_state` 报告；收到
  `can_trigger=1` 时（单 MCU）计算 `expire = clock32_to_clock64(clock) + expire_ticks`，
  比当前 `expire_clock` 大 ≥ `min_extend_ticks` 就重发 `trsync_set_timeout`；
  `can_trigger=0` 时记录 `trigger_reason` 并完成 completion；
- `stop()` 发 `trsync_trigger(REASON_HOST_REQUEST)` 并等 `trsync_state`（可用
  `call_msg`，pending call 优先于 bind_event），对每个 stepper `note_homing_end`；
- `wait_end`：记录 `home_end_clock`，收到超过它的 `trsync_state` 时主动
  `trsync_trigger(REASON_PAST_END_TIME)`。

**决定**：`motion/trsync.rs`（或 `mcu/resource/trsync.rs`）纯 Rust 单 MCU 实现；多 MCU 的
「取最慢者」逻辑留接口（`Vec<McuTrsync>`），FW6e 再补。`oneshot`/`Notify` 用 tokio。

### (c) `stepcompress` history（**建议：FW6c 补，直译**）

上游 `history_steps{first_clock,last_clock,start_position,step_count,interval,add}` 链表 +
`find_past_position(clock)`（二次方程求 offset）+ `extract_old`。FW5f 已在 `add_move` 留了
`last_position` 字段、`set_last_position(clock,position)` 留了入口。**决定**：FW6c 加
`VecDeque<HistorySteps>` 与两个方法，host 单测与上游公式对拍；`motion::Stepper` 再加
`mcu_position(cmd_pos)`/`past_mcu_position(print_time)`/`note_homing_end()`。

### (d) 回零协议放哪、长什么样（**建议：`Kinematics` 加方法，`HomingState` 是窄接口**）

FW5 笔记已定 `check_move` 走窄 `MoveContext`。回零同理：`Kinematics` 加

```rust
fn home(&mut self, homing: &mut dyn HomingState);
fn set_homed_position(&mut self, pos: Coord);
```

`HomingState`（由 `extras/homing.rs` 的 `Homing` 实现）给 kinematics 用：
`home_rails(rails, forcepos, movepos)`、`get_trigger_position(name)`、
`set_stepper_adjustment(name, adj)`、`set_homed_position`。`CartesianKinematics::home`
按上游 `cartesian.py`：对每个未回零的轴 `home_rails([rail], forcepos, movepos)`、
`set_homed_position([None,None,None])`、`update_limits(axis, None)`。

**决定**：`extras/homing.rs` 持有 `Homing`；`Kinematics` trait 加 `home`/`set_homed_position`；
`HomingState` 放 `motion/kinematics.rs`（或 `motion/homing.rs`）避免 extras 反向依赖。

### (e) `drip_move` 与滴灌式 flush（**建议：前台 paced loop，暂停后台 flush 任务**）

上游 `drip_move` 不是简单的「把 Move 塞进 trapq」：`toolhead.drip_move` →
`_drip_load_trapq`（把 Move 直接 append 到 trapq、绕过 lookahead 的 junction，
`lookahead.reset()`）→ `motion_quuing.drip_update_time(start,end,completion)`。后者是
**同步滴灌循环**（`motion_quuing.py:265-294`）：

1. `_await_flush_time(start_time)`；**关掉后台 flush 定时器**（`update_timer(flush_timer, NEVER)`）；
2. 以 `DRIP_SEGMENT_TIME=50ms` 为窗口，把 `step_gen_time`/`flush_time` 往前推，每段之间
   `completion.wait(now + wait_time)`（等触发或按 `DRIP_TIME=100ms` 节奏）；
3. 触发（或到 `end_time`）后恢复后台定时器，再冲一段 `kin_flush_delay`。

关键效果：触发一回来，flush 循环就停，不会把已规划但未发出的步继续推到固件——这就是
「回零移动被 trsync 停住」在主机侧的对应物（固件侧靠 `stepper_stop_on_trigger`）。

**本仓库的对应**：目前 `extras/toolhead.rs` 有一个 10ms 的后台 flush 任务。回零时需要一个
**前台 paced loop**：在 `G28` 的 `block_on` 里反复 `flush_step_generation(step_gen_time)` +
`send_steps_async`，每小段查一次触发 completion，期间**暂停后台任务**（一个
`drip_active` 标志或让后台任务持同把锁）。`ToolHead`/`MotionQueuing` 加
`drip_move(newpos, speed, completion)` 与 `drip_flush_until(completion)`。
`kin_flush_delay` 先用常数 `SDS_CHECK_TIME=1ms`。

### (f) multi-MCU / 其余消费者（**后置**）

`SecondarySync`、多 MCU 共享轴、`endstop_phase`、`probe`/`bltouch`、`safe_z_home`、
`manual_probe`、`bed_mesh` 全部后置；FW6 只做单 MCU cartesian 的 `G28`。`stepper_enable`
（`enable_pin`/`M18`/`M84`）是回零的常见前置，但属独立 extra，可在 FW6d 之前或之后单独排。

### (g) `G28` 的同步/异步边界（**建议：复用 `bus_debug::block_on` 桥，阻塞一个 worker**）

本仓库的 `CommandHandler` 是**同步**的（`gcode.rs`），而回零要等异步的 trsync 触发完成
（`home_wait`）并驱动滴灌 flush（见 (e)）。上游用 greenlet 把等待写得很同步；这里沿用已有的
`extras/bus_debug.rs::block_on`：在 handler 里 `tokio::task::block_in_place` +
`Handle::block_on(async homing)`，把整个 `home_rails` 跑到完成。约束与 `IIC_READ`/
`SPI_TRANSFER` 相同：需要多线程 runtime（`src/klippy.rs` 的 machine runtime 是
`worker_threads(2)`）。

- handler 阻塞 1 个 worker；**另一个 worker 继续跑** 接收任务（`trsync_state` 的报告 →
  延长 `trsync_set_timeout`）、flush 任务、反应器的定时器。这足以跑完回零，但两个 worker
  是紧的；若以后发现 flush 被饿死，可把 machine runtime 的 worker 数调大（一个小改动）。
- `block_on` 目前是 `pub(super)` 且写死 `McuError`；FW6d 把它提升为通用（或给 gcode 层一个
  `block_on` helper）。
- 另一条路是“`G28` 只发起、由事件驱动完成”，但那会破坏 `run_script` 的顺序语义；不采纳。

## 7. 风险与未决

- **滴灌 flush 与后台 flush 任务**：回零时两个驱动必须互斥（(e)）。建议用一个
  `drip_active` 标志或同一把锁；FW6d 必须写清并发边界，否则同一步会被生成两次。
- **machine runtime 只有 2 个 worker**（`src/klippy.rs:274`）：`G28` 阻塞 1 个，另一个跑
  接收/flush/定时器。回零期间如果 flush 被饿死，先调大 worker 数；真板测一下。
- **`stepper_stop_on_trigger` 必须先于移动到固件**：上游在 `trsync.start` 里就发，且用
  `reqclock=clock` 保证不早于移动。我们用 FIFO 发送顺序保证：先发 `trsync_start` +
  `stepper_stop_on_trigger` + `trsync_set_timeout`，再 `drip_move` 下发 `queue_step`。
- **通信延迟 → `REASON_COMMS_TIMEOUT`**：`expire_ticks` 是打印时长，不是墙上时长；host 忙
  （尤其 worker 紧张）时会误触发。上游用 `report_ticks=timeout*.3` + 报告延长；先照搬，
  真板看是否需要放宽 `TRSYNC_SINGLE_MCU_TIMEOUT`（0.25s）。
- **`endstop_home` 的 `pin_value` 与 `invert`**：`triggered ^ invert`，与
  `query_endstop` 的 `pin_value ^ invert` 一致；单测要盖两极性。
- **多 MCU**：`McuTrsync` 接口留 `Vec`，但「取最慢者延长」的 C 逻辑（`trdispatch.c`）
  未搬；FW6e 前不支持多 MCU 共享轴，`TriggerDispatch::add_stepper` 要像上游一样报
  config error。
- **`stepper_enable`**：`enable_pin`/`M18`/`M84` 不在 FW6 范围，但真板回零前通常要先上使能
  （步进驱动 enable 拉低）；如果板子默认使能就不阻塞，否则单独排一条小任务。
