本文记录 FW6a 第一半（清掉 FW5 运动层的单 MCU 假设）实际怎么改的、发现了什么、还剩什么。
设计依据见 [FW6 动工前调查](2026-09-21-fw6-notes.md)；规范以 `TODO.md` 与代码为准。

## 1. 问题：FW5 的三处单 MCU 假设

FW5 只按主 MCU 跑真板 `--task motion`，所以三处隐含「只有一个 MCU」：

1. `MotionQueuing { mcu_freq }`，`generate(flush_time)` 用 `move_clock = flush_time * mcu_freq`
   给**所有** stepper；
2. `extras/toolhead.rs::connect` 取 `self.axes[0].mcu_stepper().mcu()` 当唯一 MCU，
   只建一个 `McuClock`，`ToolHead::new(limits, mcu_freq)`；
3. `extras/stepper.rs::connect` 写死 `set_time(0.0, freq)`。

对副 MCU，正确映射是 `clock = (print_time - offset) * freq`（`SecondarySync`，
`clocksync.py:177-235`），`offset = main.estimated_print_time(now) - local.estimated_print_time(now)`；
`set_time(0.0, …)` 会让副 MCU 的 `queue_step` 时刻整体偏掉 `main_pt - local_pt`（可能是秒级）。

## 2. 改法

- **时钟下放到 stepper**：`StepCompressor` 本来就按自己 MCU 的 freq 建，只需把 offset 也放进去，
  并提供 `print_time_to_clock`。`MotionQueuing` 不再需要 freq，`Stepper::generate` 自己算
  flush bound。
- **时钟与对齐的下放（FW6b 开头细化）**：后来把 `McuClock` + `print_time_offset` 从 toolhead
  挪到 **`McuChip`**（`Arc<Mutex<...>>` 槽），由 `McuObject::connect` 建时钟/对齐并 `set_clock`。
  理由是 trsync/endstop 资源也要按自己 MCU 换算 print time，而它们不在 toolhead 里；
  `McuObject` 暴露 `clock()`/`print_time_offset()`/`print_time_to_clock()`/`clock32_to_clock64()`/
  `estimated_print_time()`。于是：
  1. `McuObject::connect`：`get_uptime` → 建 `McuClock` + seed；主 MCU（`name()=="mcu"`）offset=0，
     副 MCU 对齐主 MCU；`chip.set_clock(clock, offset)`。
  2. `PrinterStepper::connect`：通过 `Printer::lookup_objects_as::<McuObject>` 按 chip 名找它，
     `compressor.set_time(offset, freq)`。
  3. `ToolHeadObject::connect`：只读主 MCU 的 `estimated_print_time` 设 toolhead，不再自己建
     `McuClock`。
  `Printer` 新增 `lookup_objects_as::<T>(module)`（`lookup_objects` + downcast）。

## 3. 顺带修掉的 bug：`McuClock::seed` 没取 `CLOCK_FREQ`

`ClockEstimator::seed` 用 `self.mcu_freq` 作为 `clock_freq`，而 `McuClock::new` 里
`ClockEstimator::new(1.0)` 的初值是 **1 Hz** 占位；`McuClock::get_clock`（周期查询）会先
`set_mcu_freq(mcu.clock_freq())`，但 `seed`（连接期 `get_uptime`）不会。

后果：`seed(now, 2e8)` 后 `estimated_print_time(now) = 2e8 / 1 = 2e8` 秒，
toolhead 的 `print_time`、`BUFFER_TIME_START` 全错；真板 `G1` 一旦走这条路径就会把
`step_clock` 算到天文数字。之前没暴露是因为真板只跑过 `stress`（自己管时钟）与
`--task motion`（直接 `Stepper`，不经 `McuClock`）。

**修复**：`McuClock::seed` 先从 `mcu.clock_freq()` 取频率再 seed；加单测
`test_seed_takes_the_frequency_from_the_dictionary`（10 s @ 20 MHz → 10.0 s）。

## 4. 测试

- `motion/stepcompress.rs`：`test_print_time_to_clock_follows_the_offset`（主 0 / 副 1.5，含
  负区间 clamp 到 0）。
- `motion/stepper.rs`：`test_each_stepper_generates_in_its_own_mcu_clock`——副 MCU（2 MHz、
  offset 10）上 100 mm/s、1 mm/步 的步间隔应为 ~20000 tick，而不是漏掉偏移的 ~2e7。
- `mcu/resource/pin.rs`：`test_chip_clock_applies_the_print_time_offset`——chip 的
  `print_time_to_clock` 按 offset 换算。
- `cmd/clock.rs`：`test_seed_takes_the_frequency_from_the_dictionary`。

## 5. 留给 FW6a 第二半 / 后续

- **响应器式多实例假 MCU 挪到 FW6b 开头**：`FrameMock` 是 FIFO 精确帧匹配，endstop/trsync
  这种多消息带时序的交互用不了；而 FW6b 的 trsync/endstop 本来就需要一个能按消息类型回应、
  可开多实例的假 MCU。等它到位后，再补 `ToolHeadObject::connect` 的两 MCU 端到端。
- 时钟/对齐已随 FW6b 开头下放到 `McuObject`/`McuChip`（见 §2），trsync/endstop 可以直接用
  `McuObject::print_time_to_clock` / `clock32_to_clock64`。
- 之后继续 FW6b（endstop/trsync 命令层与多实例 `TriggerDispatch`）——命令层已完成（见
  下一节的提交列表）。
