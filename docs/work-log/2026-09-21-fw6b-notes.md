## 1. 关键设计点与差异

### (a) 一个 MCU 一个 `trsync_state` handler

`Mcu::bind_event` 只保留**一个**同名 handler（`bind_callback` 会替换），而同一 MCU 上可能有
多个 endstop（X/Y 都在主 MCU）。所以加了一个每 MCU 的 `TrsyncRegistry`：
- `McuChip` 持 `Arc<TrsyncRegistry>`；
- `McuTrsync` 在自己的 config callback（build 时，字典已就绪）里 `chip.trsync_registry().register(...)`；
- registry 首次注册时 `Mcu::bind_event::<TrsyncState>` 绑一个 router，之后按 `state.oid` 找
  `McuTrsync` 并调 `handle_state`。

上游的 `serialqueue` fastreader 按「format + oid」注册，天然支持多条；这里用 registry 达到
同样的效果。

### (b) 多 MCU 取最慢者，纯 Rust

`TriggerGroup::on_report`：每个 `McuTrsync` 存 `last_status_clock`，用各自 `chip.clock_to_print_time`
换成 print time，取最小值与次小值；最慢的 MCU 用次小值、其余用最小值，`extend_timeout` 只在
`expire - current >= min_extend_ticks` 时重发 `trsync_set_timeout`（对应
`chelper/trdispatch.c:handle_trsync_state`）。单轴单 MCU 时退化成「用自己刚报告的 clock
加 `expire_ticks`」。测试用两个 `Mcu::for_test` 验证。

### (c) 没有 host serialqueue → `query_endstop` 不按 clock 压后

上游 `query_endstop(print_time)` 用 `minclock` 把查询压到该 clock 再发；本仓库没有该队列
（FW6 拍板 a），所以查询到达即读。空闲时（`M119`）结果一致；运动中它读的是**当前**电平而
不是运动结束时的电平。已在模块文档与 `query_endstop` 的参数名（`_print_time`）标注。

### (d) `home_start`/`home_wait` 的流程

- `home_start`：`clock = print_time_to_clock(print_time)`、`rest_ticks = pt(print_time+rest_time)
  - clock`、`sample_ticks = seconds_to_clock(sample_time)`；`dispatch.start(print_time)` → 每
  trsync 发 `trsync_start` + `stepper_stop_on_trigger` + `trsync_set_timeout`；再发
  `endstop_home`（`pin_value = triggered ^ invert`）。
- `home_wait(home_end_time)`：`dispatch.wait_end(end_time)`（记 `home_end_clock`）→ await
  completion（`can_trigger=0` 的 `trsync_state` 设置 reason）→ 发 disable `endstop_home` →
  `dispatch.stop()` 发 `trsync_trigger(HOST_REQUEST)` 复位固件 → reason 失败报
  `Communication timeout during homing`、非 `EndstopHit` 返回 `0.0`、命中则查
  `endstop_state.next_clock` 换算触发 print time（`next_clock - rest_ticks`）。

## 2. 测试

- `cmd/endstop.rs` / `cmd/trsync.rs`：参数按固件顺序、`pull_up` 负数成 0xff、disable 全零、
  `TriggerReason` 映射与 `is_failure`。
- `mcu/resource/trsync.rs`：`test_a_state_report_completes_the_group`（report → completion）、
  `test_a_secondary_extends_the_slowest_mcus_timeout`（两个假 MCU，快的被慢的拉长）、
  `test_a_registry_routes_by_oid`（显式注册后按 oid 路由）。
- `mcu/resource/endstop.rs`：`home_start` 发 `endstop_home` 且 completion 未完成。
