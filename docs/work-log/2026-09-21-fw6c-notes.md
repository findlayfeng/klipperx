## 1. 关键设计点与差异

### (a) `query_endstops` 由 `[printer]` 创建

上游每个 rail 通过 `printer.load_object(config, 'query_endstops')` 按需加载；本仓库的装载器
只认 `section!`，而 `query_endstops` 没有配置节。它在 `[printer]` 的工厂里建（late 阶段，
generic 的 `[stepper_*]` 都已就绪），并用 `printer.add_object` 注册，然后登记各轴 endstop。
这样 `objects/list` 里是 `… stepper_z, query_endstops, toolhead`。

### (b) `endstop_pin` 可选（有意分歧）

上游 cartesian rail 要求 `endstop_pin`；本仓库做成可选，没有 endstop 的 `[stepper_*]` 仍能
装载（现有测试/最小配置不受影响）。`G28`（FW6e）遇到无 endstop 的轴时报配置错。

### (c) 推断 `homing_positive_dir`

照上游：endstop 位置在 `position_min + 轴向长/4` 以下 → 负向；在 `position_max - 轴向长/4`
以上 → 正向；中间无法推断则报错；`positive_dir` 与 `position_endstop == position_min/max`
的矛盾也报错。

### (d) `M119`/端点的同步→异步桥

`query_endstop` 是 async（`Mcu::call_msg`），而 `CommandHandler`/`Endpoint::handle` 同步，
沿用 `bus_debug` 的 `block_in_place` + `Handle::block_on` 桥；机器 runtime 是多线程。
`query_all_blocking` 供两处共用。

### (e) `query_endstop` 的 print_time

FW6b 已记：本仓库没有 host serialqueue，`print_time` 不用于压后查询（模块文档与参数名
`_print_time` 标注）。空闲时（`M119` 的典型场景）与上游一致。

## 2. 测试

- `extras/stepper.rs`：带 `endstop_pin` 的 `[stepper_x]` 建出 endstop 且 `homing_info` 默认
  （speed 5 → second 2.5、negative dir）；`position_endstop` 在中间时报错。
- `extras/query_endstops.rs`：脚本化 `endstop_query_state` → `endstop_state`（`pin_value=1`）
  后 `query_all` 得 `true`、`get_status.last_query` 正确；`!` 反相得 `false`；`M119` 输出。
- `api/endpoints/query_endstops.rs`：无 endstop 时端点返回 `{}`；path 名正确。
