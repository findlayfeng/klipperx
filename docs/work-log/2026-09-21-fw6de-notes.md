# FW6d–FW6f 动工记录与 FW6 收口（2026-09-21）

本文记录 FW6d（回零精度前置）、FW6e（回零协议与 `G28`）、FW6f（F3 命令队列输出）以及
**FW6 的收口**。设计依据见 [FW6 调查](2026-09-21-fw6-notes.md)；框架验收在 FW6c 已达成。

## 1. FW6d：`stepcompress` history 与 stepper 回零句柄

上游 `chelper/stepcompress.c` 的 `history_steps` 链表 + `find_past_position` 用来回答
「某个过去的 clock 时步进器在哪」，回零精度就靠它（触发 clock 在 halt 位置与上一步之间）。

- `motion/stepcompress.rs`：
  - `HistoryStep{first_clock,last_clock,start_position,step_count,interval,add}`；
  - `add_move` 记一笔（`step_count` 按 `sdir` 带符号，`last_position` 累加）；
  - `set_last_position(clock,position)` 之后压一个 marker（`interval=add=0`，`step_count=0`）；
  - `find_past_position(clock)`：新→旧遍历，段内用 `interval`/`add` 解 offset（`add!=0` 走二次方程）；
  - `extract_old(max,start,end)`、`history_expire(end_clock)`、`reset(last_step_clock)`
    （`stepcompress_reset`）。
- `motion/stepper.rs`：`mcu_position()`、`past_mcu_position(print_time)`、`history(...)`、
  `reset_compressor(clock)`。
- `mcu/resource/stepper.rs`：`reset_step_clock(clock)`。

**测试**：把 `queue_step` 序列在 Rust 里「展开」成 `(clock, position)`，与
`find_past_position` 在**每个步进 clock** 上逐点对拍（含加速段，`add!=0`）；marker 行为
（marker 之前的 clock 仍取更旧运行的结果，与上游一致）；`extract_old`/`history_expire`；
`Stepper` 的 mcu/past 位置。

## 2. FW6e：回零协议与 `G28`

### FW6e-1 运动学协议（纯逻辑）

- `motion/kinematics.rs`：`HomingInfo`、`HomeCoord = [Option<f64>;4]`、`HomingState`
  （`axes`/`homing_info`/`home_rails`）、`Kinematics::home`；`home_move()` 公有 helper
  （上游 `home_axis` 的 1.5× 轴长 forcepos）；`CartesianKinematics::home` 按轴顺序逐轴调用。
- `HomingInfo` 从 `extras/stepper.rs` 下移到 `motion`，避免 motion 反向依赖 extras。
- **测试**：`FakeHoming` 记录 `home_rails` 调用，验证 X 负向（forcepos=300）、Y 正向
  （forcepos=-100）与其余轴留 `None`。

### FW6e-2 `drip_move` 与 `G28` 驱动

- `motion/toolhead.rs`：`drip_move(newpos,speed)`（绕过 lookahead、junction 归零、直灌 trapq、
  推进 print_time）、`get_last_move_time()`、`wipe_trapq()`。
- `extras/toolhead.rs`：
  - `HomingEndstop` trait（`home_start`/`home_wait`）+ `impl for McuEndstop`，让驱动可用假
    endstop 测；
  - `home_axes`/`home_axis`：`set_position(forcepos, [axis])` → `home_start` → `dwell` →
    `drip_move(homepos)` → **小窗口滴灌 flush**（`DRIP_SEGMENT_TIME=50ms`，触发即停）→
    `home_wait` → `set_position(homepos, [axis])`、`wipe_trapq`；
  - `G28`：`Guard::take()` 把 `Connected` 拿出来 → `block_in_place` + `Handle::block_on`
    驱动 → 放回。**后台 flush 任务因共享槽位为空而自然让开**，不需要额外标志；
  - 触发 `homing:home_rails_begin/end`、`homing:homing_move_begin/end`。
- **测试**：`drip_move` 装载/生成/wipe；`FakeEndstop`（立即触发）跑 `home_axis`，断言轴落到
  endstop 位置、`homed_axes` 更新、trapq 清空。

### 已知限制（记录，不阻塞框架）

- 只做**单次回零**：上游的 `homing_retract_dist` 回抽 + 二次回零、`endstop_phase` 的
  `set_stepper_adjustment`/`get_trigger_position` 未接。
- **一次一轴**：`CartKinematics.home` 本来就是逐轴；多 rail 同时回零（delta 等）未做。
- **跨 MCU 共享轴**：✅ 已对齐上游（见 §5 末）。`TriggerDispatch::add_stepper` 在装载期为步进
  所在 MCU 按需建 `McuTrsync`（跨 MCU 的单根轴回零能停），并对同一 `stepper_` 前缀的两根
  步进落在不同 MCU 时报 `Multi-mcu homing not supported on multi-mcu shared axis`。
- **双板时序/漂移**：✅ 软件侧已实现 + 已测。次级 MCU 的 `SecondarySync` 周期重校准
  （`McuChip` 可调 `(offset,freq)`、`McuObject` 1s 定时器、toolhead flush 前刷新）已接入；
  模拟 ±100 ppm / 1 小时的漂移测试通过（映射误差 < 10 ms）。真板只剩**实际晶振漂移量**与
  电气/传输时序。
- `G28` 的假 MCU 端到端（真实 `McuEndstop`/`trsync_state`）仍缺**响应器式多实例假 MCU**
  （FW6a-2 记下）；当前用 `FakeEndstop` 覆盖驱动序列、用脚本化单次交互覆盖 `McuEndstop`。
- 真板单轴 `G28` `[~]`（待条件）。

## 3. FW6f：F3 命令队列/运动同步输出

F3 要的是「挂在命令队列上、与运动同步的输出」（上游 `extras/bus.py:337`
`MCU_bus_digital_out`）。本仓库**已经有等价能力**：`DigitalOut::queue_digital_out(clock, value)`
走固件的 `queue_digital_out oid clock on_ticks`，固件按绝对 clock 翻转，正是
`MCU_bus_digital_out` 用 `update_digital_out(minclock,reqclock)` + serialqueue 达到的效果
（见 FW6 调查 §4(a)：用固件绝对时钟命令替代 host 命令队列）。

**结论**：不新增 `MCU_bus_digital_out` 包装（它的消费者是 display `uc1701`/`st7920`，属 H8）；
等 H8 接显示时直接用 `pins.setup_digital_out` + `queue_digital_out`。F3 记为「能力已具备、
包装随消费者」。
